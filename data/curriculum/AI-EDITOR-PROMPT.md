# AI editor implementation brief — StudySprint, first and second year

Extend the existing StudySprint repository using this pack and the official university source https://uktech.ac.in/en/page/syllabus. Inspect the current architecture and existing features first. Preserve the student's existing content and progress. Implement the first-year and second-year curriculum for every one of the 21 main branch entries in curriculum-catalog.json, with separate first/second/third/fourth semester mappings. Do not stop after CSE, Mechanical, Electrical or Civil.

## Academic structure

- Model university, college, programme, admission batch, curriculum version, official branch, college branch alias, academic year, semester, course offering, unit and topic separately. Store the student's current semester independently from their admission batch.
- First year: use the common 2022–23-onwards source for Sem I and II where applicable. Preserve each alternative subject pair and obtain college/batch/section allocation before activating a student timetable. Do not assign both alternatives automatically. Include practical subjects, induction, proficiency, the first-year internship rule and Biotechnology's conditional bridge courses. Do not count the same first-year internship twice.
- Second year: import each branch's own Sem III and IV mappings, including theory, labs, mandatory non-credit courses, optional/minor choices, and vacation internship requirements. A vacation internship listed after Sem IV may be assessed in Sem V; keep completion and assessment semesters separate.
- Keep AIML and CSE(AI/ML), Cyber Security and CSE(Cyber Security), EE and EEE as separate branches. Similar subject lists do not justify merging degree identities. Treat RIT's CSE++ as an unresolved college alias until its official registration/course mapping is supplied.
- Store shared courses once only after equivalence is verified. A course code alone is not a global key: titles and course contents differ between sources, and some printed codes conflict. Use versioned course IDs and explicit branch-course mappings.
- Keep the two archived 2019–20 branches (Petroleum and Bio Chemical) separate from the 21 main entries. Keep the eight optional specializations as optional tracks, not additional degree branches. The presence of a branch in the university catalogue does not mean RIT offers it; configure college offerings separately.

## Import and content work

- This pack maps curriculum tables, not a finished unit/topic database. Follow each official PDF to extract the unit/topic details and lab exercises for the relevant first two years. Retain source URL, PDF page, effective/admission scheme, extraction timestamp and source checksum. Do not fabricate missing units or mark course-table extraction as complete content extraction.
- Validate all flagged entries, including EEE's embedded EE draft heading, CSE Sem IV credits, Biotechnology's Cyber Security code and Polymer's repeated theory/lab code. Preserve the original printed value and hold unresolved mappings in draft. Do not guess corrections.
- Build a repeatable, idempotent importer with validation and preview. Re-running it must not duplicate courses or erase student progress. University source updates should create a reviewable new version, not silently rewrite existing students' curriculum.
- Store official syllabus content separately from authored notes, generated practice questions, previous papers and model answers. A question generated by AI must never be labelled an actual CIA/PYQ question.
- The university's complete syllabus does not define RIT's CIA1/CIA2 unit coverage. Add per-college/batch/semester/subject exam scope, exam date and paper-pattern configuration. Leave unknown scopes visibly unconfigured. Retain full syllabus access while explaining that exam-specific planning needs this configuration.

## Student experience

- Onboarding: college, admission batch, official branch/confirmed alias, current semester, exam type (CIA1, CIA2, semester examination), exam dates and daily available study time. Display only that student's applicable subject allocation.
- Connect the imported content to all existing features: custom-day study plans, My Subjects, unit/topic checklists, completed/weak/not-started status, chapter-wise short/long/numerical questions, step-by-step solutions, quizzes with a custom question count, revision tracking, priority view and quick last-day revision.
- Make priority depend on the confirmed exam scope, remaining time, unstudied topics and weak topics. Do not make up marks or weightage. If the requested quiz count exceeds available relevant questions, explain the limit instead of silently duplicating questions.
- Preserve the dark theme, responsive navigation, Smart Lab and study assistant. Ground study answers in the selected course/version and display syllabus citations when relevant. Say when supporting material is missing. Code execution must report actual runner output; AI debugging explanations are a separate action. Keep student code in an isolated runner with resource/time limits, not in the web application process.
- Keep personal progress scoped to the authenticated user and curriculum offering. Branch changes must not overwrite another student's data or destroy earlier progress. Existing local progress needs an explicit, non-destructive migration path if the app adds accounts.

## Completion evidence

Provide a coverage matrix with 21 branches, Sem I–II applicability and separate Sem III–IV results. Every source-table row must be accounted for or explicitly flagged; every unit/topic content gap must remain visible. Include checks for all branch mappings, subject alternatives, bridge eligibility, archived versions, lab/theory code conflicts, repeat imports and student progress isolation. Validate existing study-plan, question-bank, custom-quiz, revision and assistant flows with representative first-year and second-year students. Run appropriate repository checks. Report implemented features and genuine unresolved source/college decisions separately. Do not claim the entire import is finished while only CSE or placeholder content works.
